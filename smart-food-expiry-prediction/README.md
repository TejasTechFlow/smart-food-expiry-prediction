# Smart Food Expiry Prediction System

A beginner-friendly ML web app that estimates the **shelf life of food** from its storage conditions.
**Important:** the model is trained on a **synthetic educational dataset**. Predictions are estimates and
**do not say whether food is safe to eat**. Never override package dates or food-safety guidance.

## Objectives
Demonstrate a full ML workflow (dataset → pipeline → model → API → GUI) and help reduce food waste.

## Features
Landing page, dashboard (cards + 3 Chart.js charts from the database), prediction form with validation,
result card with progress bar and report download, food inventory (add/edit/delete/search/filter/sort),
prediction history (search, category/date filters, sort, details, delete, CSV export), About page.

## Tech stack
HTML/CSS/JS, Bootstrap 5, Chart.js, Font Awesome | FastAPI, Uvicorn, Pydantic | SQLite + SQLAlchemy |
pandas, NumPy, scikit-learn (Random Forest), Joblib.

## Architecture
`frontend/` (static pages, `js/api.js` = all fetch calls) → HTTP/JSON → `backend/app/` (routes → services/predictor →
saved Joblib pipeline; SQLAlchemy → `food_expiry.db`). `backend/ml/train_model.py` creates dataset and model.

## Machine learning methodology
* **Target:** *total shelf life in days* (from start of storage). Not food age.
  `remaining = total − storage_duration_days` (min 0); `expiry date = purchase date + total shelf life`.
* **Features:** category, storage type, packaging, freshness condition, temperature (°C), humidity (%RH).
  Storage duration is *not* a feature; it is only used to convert total life to remaining life.
* **Preprocessing:** duplicate removal, missing/invalid checks, one-hot encoding inside a scikit-learn `Pipeline`
  (fitted on the training split only). 80/20 train/test split.
* **Models compared on the test set:** mean baseline, Linear Regression, Gradient Boosting, **Random Forest (used)**.
  Metrics: MAE, RMSE, R² (see `backend/models/metrics.json` or the About page). High R² here only shows the model
  recovers the *synthetic rules*; it says nothing about real food.
* **Constraints:** predictions must be finite, ≥ 0.1 day and ≤ a per-category maximum (e.g. Meat 365 days).
  If the model file is missing the API answers **503**; it never invents a result.
* **Status thresholds (days left):** Fresh > 7 · Use Soon 3–7 · Near Estimated Expiry 1–2 · Estimated Shelf Life Exceeded ≤ 0.
  Inventory status is recomputed live from the expiry date and today's date.

## Dataset
`backend/ml/dataset.csv` – 4,000 rows generated by `train_model.py` from assumed base shelf lives per category/storage,
a temperature factor (doubling per 10 °C cooler), humidity, packaging and freshness factors plus noise.
Units: °C, % RH, days. **Not real measurements.**

## Setup on Windows (PowerShell, from the project root)
```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r backend/requirements.txt
python backend/ml/train_model.py                      # creates dataset.csv + models/food_expiry_model.joblib
python -m uvicorn app.main:app --app-dir backend --reload --port 8000    # terminal 1 (DB tables are created on startup)
python -m http.server 5500 --directory frontend                          # terminal 2
```
Open http://localhost:5500 (frontend) and http://localhost:8000/docs (API docs).
If PowerShell blocks activation: `Set-ExecutionPolicy -Scope Process Bypass`.
Use `localhost:5500` or `127.0.0.1:5500` (the only allowed CORS origins; edit `backend/app/main.py` to change).

## API
| Method | Path | Purpose |
|---|---|---|
| GET | /api/health | API, model and database status |
| GET | /api/categories | Categories, storage/packaging options, thresholds |
| POST | /api/predict | Predict; also logs the prediction to history |
| POST/GET | /api/foods | Save (optional `prediction_id` links history) / list (`search,category,status,sort`) |
| GET/PUT/DELETE | /api/foods/{id} | Read / update (re-predicts) / delete |
| GET | /api/history | List (`search,category,date_from,date_to,sort`) |
| DELETE | /api/history/{id} | Delete a record |
| GET | /api/model/metrics | Saved metrics and dataset info |
| GET | /api/stats | Dashboard numbers (extra endpoint) |

## Tests
```powershell
python -m pytest backend/tests -v
```
Covers health, model loading, valid/invalid predictions, humidity range, freezer vs. negative temperatures,
date maths, CRUD, history persistence/filters and an end-to-end predict → save → inventory test (temporary database).

## Known limitations
Synthetic data; few features; no real-world validation; no automated browser/JS tests (frontend error handling is in `js/api.js`
and was only reviewed manually); the prediction result is shown on the Predict page rather than a separate page.

## Future scope
Real shelf-life data, barcode scanning, expiry reminders, per-product models, user accounts.
